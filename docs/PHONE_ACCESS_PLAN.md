# 폰 접속 계획 (초안, 실행 금지)

- 작성: PM, 2026-11-16 KST. 상태: **초안. 이 문서의 명령은 하나도 실행하지 않았다.**
- 실행 주체: CTO가 CEO에 사전 통보한 뒤 직접 실행한다. PM과 서브 에이전트는 실행하지 않는다(저장소 규칙 9).
- 표시: [확인됨] 저장소 코드·테스트로 확인 / [미확인] 실행 전 공식 문서로 다시 대조할 것

## 1. 목적과 지금 상태

목적: 얼큰이님이 폰에서도 맥미니의 Z2H 앱과 진도를 이어 보게 한다. 공개 배포가 아니라 본인 이메일로만 들어오는 잠긴 주소다.

지금 상태 [확인됨]
- 진도 서버는 `127.0.0.1:8787`에만 열린다. 다른 주소로는 실행을 거부한다.
- 서버는 `Host`가 `127.0.0.1`·`localhost`일 때만 응답한다. 터널 주소는 `Z2H_EXTRA_HOSTS`, `Z2H_EXTRA_ORIGINS`에 넣어야 통과한다.
- 터널, Access 정책, DNS, 방화벽은 만들거나 바꾼 것이 없다.

## 2. 먼저 풀어야 할 문제: 폰에서 로그인할 수단이 없다

- 지금 로그인은 "개발용 로그인"뿐이다. 비밀번호 없이 계정을 고르는 방식이라, 이 컴퓨터 안에서 직접 온 요청에서만 동작하게 막아 두었다.
- 터널을 거친 요청은 개발용 로그인을 쓸 수 없다. `Z2H_EXTRA_HOSTS`에 터널 주소를 넣는 순간 개발용 로그인이 통째로 꺼지고, 진도를 읽고 쓰는 요청은 모두 401이 된다 [확인됨: `server/tests/test_dev_auth_lock.py`].
- 이렇게 막은 이유: 터널 프로그램(cloudflared)은 맥미니 안에서 서버에 접속한다. 접속 주소만 보면 바깥 사람도 "이 컴퓨터 안 요청"으로 보여, 아무 계정으로나 들어올 수 있게 된다.
- 결론: **실제 로그인이 생기기 전에는 터널을 붙여도 폰에서 화면만 열리고 진도는 쓰지 못한다.**

선택지 (CTO·CEO 결정 필요)
| 안 | 내용 | trade-off |
|---|---|---|
| A (추천) | Cloudflare Access가 확인한 이메일을 서버가 믿는 `AccessAuth`를 `AuthAdapter` 뒤에 추가. Access가 요청에 붙이는 서명 토큰(JWT)을 서버가 검증하고, 그 이메일을 `auth_identity`의 계정에 잇는다 | 메일 발송·OAuth를 우리가 만들지 않아도 됨. Access 설정과 토큰 검증 코드가 필요. 로그인 기능 추가라 승인 항목인지 확인 필요 |
| B | 이메일 코드·Google 로그인(D44)을 먼저 구현 | 일반인 서비스와 같은 길. 메일 발송·OAuth 키가 필요해 공개 승인 항목 |
| C | 폰 접속을 로그인 구현 뒤로 미룸 | 지금 할 일 없음. 폰에서 이어 보기는 그때까지 불가 |

A안의 Access 토큰 머리말 이름과 검증 방법(공개 키 주소, audience 값)은 [미확인]이다. 구현 전에 Cloudflare 공식 문서로 확인한다.

## 3. 구성 그림 (A안 기준)

```
폰 브라우저
   │  https://z2h.<얼큰이 도메인>   (주소는 CTO가 정함)
   ▼
Cloudflare Access  ── 정책: 얼큰이님 이메일 1개만 허용, 그 밖은 거부
   │  통과한 요청만
   ▼
Cloudflare Tunnel (맥미니의 cloudflared 가 바깥으로 거는 연결. 맥미니에 포트를 열지 않음)
   │  http://127.0.0.1:8787
   ▼
Z2H 진도 서버 (127.0.0.1 바인드 그대로) ── SQLite
```

- 맥미니 방화벽·공유기 포트는 열지 않는다. 터널은 맥미니에서 바깥으로 나가는 연결이다.
- 서버 바인드는 `127.0.0.1` 그대로 둔다. `0.0.0.0`으로 바꾸지 않는다.

## 4. 단계별 스크립트 초안 (실행 금지, [미확인] 실행 전 공식 문서 대조)

아래는 순서를 보이기 위한 초안이다. 명령 이름과 옵션은 cloudflared 버전에 따라 다를 수 있다.

1. Cloudflare 계정에 로그인한다(브라우저 창이 열림. 로그인은 사람이 한다).
```
cloudflared tunnel login
```
2. 터널을 만든다. 터널 인증 파일이 `~/.cloudflared/`에 생긴다(비밀값. 저장소에 넣지 않는다).
```
cloudflared tunnel create z2h
```
3. 설정 파일을 쓴다(저장소 밖 `~/.cloudflared/config.yml`. 아래는 모양만).
```
tunnel: z2h
credentials-file: <2번에서 생긴 파일 경로>
ingress:
  - hostname: z2h.<도메인>
    service: http://127.0.0.1:8787
  - service: http_status:404
```
4. DNS 이름을 터널에 잇는다(DNS 변경. CEO 사전 통보 대상).
```
cloudflared tunnel route dns z2h z2h.<도메인>
```
5. Cloudflare 대시보드(Zero Trust)에서 Access 애플리케이션을 만들고 정책을 "얼큰이님 이메일 1개만 허용"으로 둔다. **Access 정책을 먼저 만들고 확인한 뒤에 6번을 한다**(순서가 바뀌면 잠기지 않은 주소가 잠깐 열린다).
6. 서버를 터널 주소를 허용한 상태로 켠다(이때 개발용 로그인은 자동으로 꺼진다).
```
Z2H_EXTRA_HOSTS=z2h.<도메인> Z2H_EXTRA_ORIGINS=https://z2h.<도메인> ../.venv/bin/python -m z2h_server
```
7. 터널을 켠다.
```
cloudflared tunnel run z2h
```

## 5. 확인할 것 (실행한 사람이)

- 허용한 이메일이 아닌 계정으로 열면 Access 화면에서 막힌다.
- 로그인하지 않은 채 주소를 직접 요청하면(예: 다른 기기의 curl) 서버 응답이 아니라 Access 로그인 화면이 온다.
- 터널을 거친 요청으로 `/api/dev-auth/accounts`를 부르면 404다(개발용 로그인이 꺼져 있음).
- 맥미니에서 `lsof -iTCP -sTCP:LISTEN -P | grep 8787` 결과가 `127.0.0.1:8787` 한 줄이다.
- A안을 구현했다면: Access를 통과한 이메일의 계정으로만 진도가 읽히고 써진다.

## 6. 되돌리는 법

1. 터널을 끈다: `cloudflared tunnel run`을 돌린 창에서 Ctrl + C.
2. 서버를 끄고 `Z2H_EXTRA_HOSTS`, `Z2H_EXTRA_ORIGINS` 없이 다시 켠다(개발용 로그인이 다시 켜진다).
3. Access 애플리케이션과 DNS 이름을 Cloudflare 대시보드에서 지운다.
4. 터널을 지운다: `cloudflared tunnel delete z2h`. `~/.cloudflared/`의 인증 파일도 지운다.

## 7. 위험

| 위험 | 대응 |
|---|---|
| Access 정책 없이 터널이 먼저 열림 | 4절 5번을 6·7번보다 먼저. 확인 뒤 진행 |
| 터널 인증 파일 유출 | 저장소 밖 `~/.cloudflared/`에만. `.gitignore`와 gitleaks 검사 유지 |
| 개발용 로그인이 바깥에 노출 | 서버가 전달 머리말·Host·허용 주소 설정으로 삼중으로 막음 [확인됨]. 설정을 바꿔 우회하지 않는다 |
| 서버 프로세스를 여러 개 띄움 | 동기화 번호(server_seq)와 쓰기 잠금이 프로세스 1개 기준. 1개만 띄운다 |
| 공개 서비스로 오해 | 이 구성은 1인용 잠긴 주소다. 일반 사용자 공개(서버 공개 운영)는 얼큰이 승인 항목이며 이 문서 범위가 아니다 |
