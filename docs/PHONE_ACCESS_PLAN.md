- 상태: **초안. 이 문서의 명령은 하나도 실행하지 않았다.** 로그인 장치도 구현하지 않았다(안만 적음).
- 실행 주체: CTO가 CEO에 사전 통보한 뒤 직접 실행한다. PM과 서브 에이전트는 실행하지 않는다(저장소 규칙 9).
- 표시: [확인됨] 저장소 코드·테스트로 확인 / [미확인] 실행 전 공식 문서로 다시 대조할 것

## 1. 목적과 정해진 것

목적: 얼큰이님이 폰에서도 맥미니의 Z2H 앱과 진도를 이어 보게 한다. 공개 배포가 아니다.

정해진 것(CTO 22:35)
- Tailscale의 `serve`만 쓴다. 얼큰이님 tailnet(본인 기기끼리만 이어진 사설망) 안에서만 열린다.
- **Funnel(인터넷 전체에 여는 기능)은 쓰지 않는다.**
- 서버 바인드는 `127.0.0.1` 그대로. 맥미니 방화벽·공유기 포트를 열지 않는다.

지금 상태 [확인됨]
- 진도 서버는 `127.0.0.1:8787`에만 열리고 다른 주소로는 실행을 거부한다.
- 서버는 `Host`가 `127.0.0.1`·`localhost`일 때만 응답한다. 다른 이름은 `Z2H_EXTRA_HOSTS`, `Z2H_EXTRA_ORIGINS`에 넣어야 통과한다.
- Tailscale 설정은 만들거나 바꾼 것이 없다.

## 2. 먼저 풀어야 할 문제: 폰에서 로그인할 수단이 없다

- 지금 로그인은 "개발용 로그인"뿐이다. 비밀번호 없이 계정을 고르는 방식이라, 이 컴퓨터 안에서 직접 온 요청에서만 동작하게 막아 두었다.
- Tailscale serve도 맥미니 안의 Tailscale 프로그램이 서버에 대신 접속하는 방식(프록시)이다. 그래서 서버가 보기에는 "이 컴퓨터 안 요청"이지만 전달 머리말이 붙고 Host가 tailnet 이름이다.
- 서버는 이런 요청에서 개발용 로그인을 거부한다. `Z2H_EXTRA_HOSTS`에 tailnet 이름을 넣는 순간 개발용 로그인이 통째로 꺼지고, 진도를 읽고 쓰는 요청은 모두 401이 된다 [확인됨: `server/tests/test_dev_auth_lock.py`].
- 결론: **로그인 장치가 생기기 전에는 serve를 켜도 폰에서 화면만 열리고 진도는 쓰지 못한다.**

로그인 장치 안 (구현하지 않음. 로그인·인증은 보안 변경이라 CTO에 올려 결정받는 항목)
| 안 | 내용 | trade-off |
|---|---|---|
| A (추천) | `AuthAdapter` 뒤에 `TailscaleAuth` 추가. serve가 요청에 붙이는 "누가 접속했는지" 머리말(Tailscale 계정 로그인 이름)을 서버가 읽어 `auth_identity`의 계정에 잇는다. 이 머리말은 이 컴퓨터 안에서 온 요청에서만 믿는다 | 메일 발송·OAuth를 만들지 않아도 됨. tailnet에 들어온 기기만 접속하므로 1인용에 맞음. 머리말 이름과 붙는 조건은 [미확인] |
| B | 이메일 코드·Google 로그인(D44)을 먼저 구현 | 일반인 서비스와 같은 길. 메일 발송·OAuth 키가 필요해 공개 승인 항목 |
| C | tailnet 안 요청에 한해 개발용 로그인을 허용하는 설정 추가 | 가장 빨리 됨. tailnet에 다른 사람·기기를 공유하면 그 사람이 아무 계정으로나 들어올 수 있어 권하지 않음 |
| D | 폰 접속을 로그인 구현 뒤로 미룸 | 지금 할 일 없음 |

A안에서 확인할 것 [미확인]: serve가 붙이는 사용자 머리말의 정확한 이름, 태그된 기기나 공유받은 사용자일 때 머리말이 빠지는지, 바깥에서 같은 이름의 머리말을 넣어 보내면 serve가 지우는지.

## 3. 구성 그림

```
폰 (Tailscale 앱 로그인, 같은 tailnet)
   │  https://<맥미니 이름>.<tailnet 이름>.ts.net
   ▼
맥미니의 Tailscale (serve: tailnet 안에서만 받음, HTTPS 인증서 자동)
   │  http://127.0.0.1:8787
   ▼
Z2H 진도 서버 (127.0.0.1 바인드 그대로) ── SQLite
```

## 4. 단계별 스크립트 초안 (실행 금지, [미확인] 실행 전 공식 문서 대조)

명령 이름과 옵션은 Tailscale 버전에 따라 다르다. 아래는 순서를 보이기 위한 초안이다.

1. 맥미니와 폰이 같은 tailnet에 로그인돼 있는지 본다.
```
tailscale status
```
2. 지금 serve·Funnel 설정이 비어 있는지 본다. 예전에 지운 프로그램의 공유 규칙이 남아 있을 수 있으니 먼저 확인한다.
```
tailscale serve status
```
3. 서버를 tailnet 이름을 허용한 상태로 켠다(이때 개발용 로그인은 자동으로 꺼진다).
```
Z2H_EXTRA_HOSTS=<맥미니 이름>.<tailnet 이름>.ts.net Z2H_EXTRA_ORIGINS=https://<맥미니 이름>.<tailnet 이름>.ts.net ../.venv/bin/python -m z2h_server
```
4. tailnet 안에서만 8787을 잇는다. **`tailscale funnel` 명령은 쓰지 않는다.**
```
tailscale serve --bg 8787
```
5. 설정을 다시 보고 Funnel이 꺼져 있는지 확인한다.
```
tailscale serve status
```

## 5. 확인할 것 (실행한 사람이)

- 폰(같은 tailnet)에서 주소가 열린다. Tailscale을 끈 폰이나 tailnet 밖 기기에서는 열리지 않는다.
- `tailscale serve status`에 Funnel 표시가 없다.
- 폰에서 `/api/dev-auth/accounts`를 부르면 404다(개발용 로그인이 꺼져 있음).
- 맥미니에서 `lsof -iTCP -sTCP:LISTEN -P | grep 8787` 결과가 `127.0.0.1:8787` 한 줄이다.
- A안을 구현했다면: 얼큰이님 Tailscale 계정으로 접속한 요청만 그 계정의 진도를 읽고 쓴다.

## 6. 되돌리는 법

1. serve 규칙을 지운다: `tailscale serve reset` [미확인: 버전별 명령]. `tailscale serve status`가 비었는지 본다.
2. 서버를 끄고 `Z2H_EXTRA_HOSTS`, `Z2H_EXTRA_ORIGINS` 없이 다시 켠다(개발용 로그인이 다시 켜진다).
3. 서버나 앱을 지울 때는 serve 규칙도 함께 지운다. 규칙은 Tailscale 쪽 설정이라 앱을 지워도 남는다.

## 7. 위험

| 위험 | 대응 |
|---|---|
| Funnel이 켜져 인터넷에 열림 | `tailscale funnel` 명령을 쓰지 않는다. 4절 5번에서 확인 |
| tailnet을 다른 사람과 공유 | 공유하면 그 사람도 주소를 열 수 있다. 로그인 장치(A안)가 계정을 나누지만, C안이면 구분이 없다 |
| 개발용 로그인이 tailnet에 노출 | 서버가 전달 머리말·Host·허용 주소 설정으로 삼중으로 막음 [확인됨]. 설정을 바꿔 우회하지 않는다 |
| 남은 serve 규칙 | 되돌리는 법 3번. 나중에 다른 프로그램이 8787을 쓰면 그 프로그램이 tailnet에 열린다 |
| 서버 프로세스를 여러 개 띄움 | 동기화 번호(server_seq)와 쓰기 잠금이 프로세스 1개 기준. 1개만 띄운다 |
