## 0. 이 문서를 읽는 법

**이 설계의 기준(원본 브리프)**
- 학습자: 얼큰이님. 비개발자이고 코드를 읽지 못합니다. 목표는 10편 전부를 영상만 보는 것이 아니라 **100% 직접 실습**해서 익히는 것입니다. 그래서 코드 한 줄마다 한국어 풀이, 단계별 따라 하기, 확인 문제, 막힘 힌트를 모든 단계에 붙입니다.
- 영상 길이(편별, research 초 단위): 01 2:25:52 · 02 1:57:45 · 03 1:15:40 · 04 1:55:57 · 05 1:55:24 · 06 0:56:21 · 07 1:56:20 · 08 0:42:40 · 09 2:13:34 · 10 4:01:26. 편별 길이를 더하면 69,659초(약 19시간 21분)입니다. 원본 브리프의 "약 19.6시간", research README의 "약 19시간 41분"과 조금 다릅니다. 이 설계는 편별 길이를 기준으로 씁니다(결정 D20, 미확인 목록).
- 실행 환경: **맥미니(M4, MPS) 로컬 Jupyter 또는 Google Colab 무료**, 두 길을 똑같이 지원합니다. 앱은 편마다 노트북(단계별 셀 자리), 단계, 정답 대조를 줍니다. MPS는 맥의 GPU를 PyTorch에서 쓰는 방식입니다. 편마다 어느 기기가 좋은지는 각 편 머리 표의 "환경" 칸에 적었습니다.
- 10편 GPT-2 재현: 원본은 8xA100급 GPU가 필요합니다. 기본은 **축소판(작은 데이터, 짧은 학습)으로 전 과정을 실습**하고, 원본 규모 재현(클라우드 GPU 유료)은 결제라 얼큰이님 별도 승인 대상입니다. 앱은 원본 규모를 실행하지 않고 안내만 합니다.
- 영상: 전체 재배포 금지. 링크와 타임스탬프만 씁니다. 앱 화면 구조(PM 보충)의 공식 임베드는 같은 영상을 같은 시작 초로 여는 링크의 한 형태로 보고, 임베드를 못 쓰는 환경에서도 "유튜브에서 이 초부터 열기" 링크만으로 모든 단계가 성립하게 했습니다(결정 D17). 자막은 분석용이며 옮기지 않습니다.

- **단계**: 앱의 한 화면. 영상 한 조각을 보고, 코드 몇 줄을 직접 치고, 결과를 보고, 그 뜻을 읽습니다.
- **구간(초)**: 영상의 시작 초~끝 초. 모두 research의 공식 챕터 시각에서 바꾼 값입니다. 챕터 하나를 여러 단계로 나눈 경우, research에 세부 시각이 없으므로 같은 챕터 구간을 함께 씁니다(표에 "같은 구간"으로 적음).
- **줄**: 학습자가 새로 치는 코드 줄 수. 앞 셀에 넣는 줄, 바꾸는 줄, 새 셀에 치는 줄을 모두 셉니다(보수적으로 셈). 붙여 넣기만 하는 준비 코드와 옮겨 붙이는 줄은 따로 적습니다.
- **종류**: `code`(코드 실습) · `read`(영상과 글 읽기) · `reflect`(내 말로 정리하거나 손으로 쓰기) · `optional`(선택).
- 숫자 표기: "계산값"은 코드를 손으로 계산해 얻은 값이고 아직 실행 검증 전입니다. research에 없는 영상 속 출력값은 적지 않고 "실행 결과로 채움"으로 둡니다.

## 1. 설계 원칙

1. **한 단계에 생각 하나.** 새 코드는 5줄 이하가 기본입니다. 6~10줄은 "(긴 단계)"로 표시하고, 10줄을 넘기지 않습니다. 길면 쪼갭니다.
2. **영상이 먼저, 손이 바로 뒤.** 챕터 순서를 그대로 따라갑니다. 학습자가 "영상의 어디쯤인지" 늘 알 수 있게 합니다. 챕터를 하나도 빼지 않습니다. 코드가 없는 챕터도 읽기나 정리 단계로 붙입니다.
3. **실행 전에 예측.** 단계마다 "보여야 하는 것"을 먼저 보여 주고, 확인 문제의 3분의 1 정도는 "결과 예측"으로 둡니다. 예측이 틀리는 순간이 가장 많이 배우는 순간입니다.
4. **일부러 틀려 보기.** 영상에 나오는 버그(기울기 덮어쓰기, zero_grad 빠뜨리기, keepdim 빠뜨리기, BatchNorm 차원 버그)는 피하지 않고 그대로 겪게 합니다. 겪은 뒤 "버그 고치기" 문제로 한 번 더 확인합니다.
5. **숫자가 영상과 달라도 정상일 수 있다고 먼저 말한다.** research가 짚은 버전 차이(02편 `torch.multinomial`, 05편 `exact: False`, 10편 cpu와 mps 차이)는 해당 단계의 첫 힌트와 "보여야 하는 것"에 미리 적고, 정답 대조는 정확한 값보다 범위와 모양(shape: 표의 가로세로 크기)으로 합니다.
6. **기초는 필요한 때 꺼내 쓴다.** 사전 기초는 15개 작은 단위로 쪼갰습니다. 진단은 추천만 하고, 각 편 시작 화면이 그 편에 필요한 단위 중 아직 안 익힌 것을 다시 권합니다. 힌트 2단계(H2)는 늘 해당 기초 단위를 가리킵니다.
7. **비개발자가 막히는 네 곳을 먼저 막는다.**
   - 셀 실행 순서: 클래스를 고친 단계에는 "다시 실행할 셀" 목록(`rerun_first`)을 반드시 붙입니다.
   - 에러 화면: 기초 단위 F-P8에서 "마지막 줄부터 읽기"를 먼저 연습합니다.
   - 모양(shape): 03편부터 텐서를 다루는 단계는 "보여야 하는 것"에 모양을 적고, 06편에는 층마다 모양을 찍는 단계를 넣습니다.
   - 기기 차이: GPU가 필요한 10편 구간은 어느 기기에서도 에러 없이 도는 "스위치 코드"로 만들고, 속도 숫자는 영상 수치를 읽어 표로 채우게 합니다.
8. **익힘은 세 가지로 본다.** 단계를 다 했는가, 문제 점수가 기준을 넘었는가, 빈 화면에서 핵심 조각을 다시 만들 수 있는가(재구성 과제). 셋 다 되면 그 편을 익힌 것으로 봅니다.
9. **원본 코드 출처.** micrograd, makemore, nn-zero-to-hero, nanoGPT, minbpe(MIT) 코드는 출처를 밝히고 씁니다. build-nanogpt(라이선스 표기 없음)는 코드를 옮기지 않고 링크만 둡니다. 10편 코드는 같은 일을 하는 nanoGPT(MIT) 코드와 우리가 새로 쓴 코드로 채웁니다. ng-video-lecture(07편 영상용 저장소)의 라이선스는 research에 없어 미확인입니다(9절 결정 목록).

### 2-2. 단위별 상세 (cc-writer용)

각 단위는 "설명 카드 1장(쉬운 말 5~8문장, 일상 비유 하나) → 실습 3개 → 문제 3개" 순서입니다. 아래 표의 "치는 것"은 줄 단위 요지이고, 정확한 코드는 writer가 씁니다. 문제 힌트는 H1(질문), H2(설명 카드의 해당 문장 가리키기), H3(빈칸 코드), H4(풀이) 4단계를 모두 붙입니다.

#### F-P1 노트북 다루기(맥미니 Jupyter, Colab)
- 목표: 노트북(코드 칸과 결과가 한 화면에 쌓이는 문서)을 맥미니 로컬 Jupyter나 Colab에서 열고, 셀에 코드를 쳐서 실행하고, 셀 왼쪽 번호로 실행 순서를 읽고, 꼬이면 다시 시작해 위에서부터 다시 돌릴 수 있다. 두 길의 메뉴 이름이 다르므로 화면 글에 둘 다 적는다(Colab "런타임 다시 시작" = Jupyter "Kernel 다시 시작").
- 길 고르기: 앱의 편별 노트북은 "Colab에서 열기" 단추와 "맥미니용 파일 받기" 단추를 함께 둔다. 맥미니 길은 Jupyter가 이미 준비돼 있다는 전제이고, 설치 안내는 이 단위에 넣지 않는다(설치는 CTO 쪽 준비, 미확인). 1~9편은 어느 길이든 되고, 07편 최종 학습과 10편은 맥미니(MPS) 또는 Colab GPU가 낫다. 맥미니 길이면 설명 카드에 "`torch.backends.mps.is_available()`가 `True`면 맥미니 GPU를 쓸 수 있다"는 안내 한 줄만 둔다(실습 단계로 세지 않음).
- 비유: 셀은 계산기 한 줄. 위에서 만든 값은 컴퓨터 기억에 남고, 다시 시작하면 기억이 지워진다.

#### F-P3 리스트와 for 문
- 목표: 리스트를 만들고, 0부터 세는 번호로 꺼내고, 잘라 내고(`[1:]`), `for`, `range`, `zip`, `enumerate`, 리스트 한 줄 만들기(`[x*x for x in ...]`)를 쓴다.
- 비유: 리스트는 번호표가 0번부터 붙은 줄 선 사람들.

| ID | 치는 것 | 보이는 것 | 뜻 |

| F-M4-S1 | `counts = [6, 3, 1]`, `total = sum(counts)`, `probs = [c / total for c in counts]` | `[0.6, 0.3, 0.1]` | 합이 1 |
| F-M4-S2 | `import random`, `random.seed(0)`, `random.choices(["a", "b", "c"], weights=probs, k=10)` | 10개 중 a가 가장 많음(정확한 결과는 실행으로 확인) | 확률대로 뽑기. 시드는 결과를 고정 |
| F-M4-S3 | `0.6 * 0.3`, `math.log(0.6) + math.log(0.3)`, `math.log(0.18)` | `0.18`, 둘째와 셋째가 같은 값 | 곱의 로그 = 로그의 합 |

| ID | 유형 | 묻는 것 | 정답 | 확인하는 것 |
|---|---|---|---|---|
| F-M4-Q1 | predict | 개수 `[2, 2, 4]`를 확률로 바꾼 뒤 마지막 값 | 0.5 | 정규화 |
| F-M4-Q2 | choice | 확률 1000개를 곱하면 생기는 문제와 해결 | 너무 작아져 0이 됨, 로그를 더한다 | 로그를 쓰는 이유 |
| F-M4-Q3 | explain | 시드(seed)를 고정하면 무엇이 좋은가 | 매번 같은 결과라 비교할 수 있다 | 재현성 |

#### F-M5 평균, 표준편차, 분포
- 목표: 평균(가운데), 표준편차(퍼진 정도)를 계산하고, 히스토그램(값이 어디에 몇 개 있는지 막대그림)을 읽고, 정규분포(`torch.randn`, 종 모양)를 알고, 표준화(`(x - 평균) / 표준편차`)를 한다. n으로 나누는 것과 n-1로 나누는 것이 조금 다르다는 것을 본다.

| ID | 치는 것 | 보이는 것 | 뜻 |
|---|---|---|---|
| F-M5-S1 | `x = torch.tensor([2., 4., 4., 4., 5., 5., 7., 9.])`, `x.mean()`, `((x - x.mean()) ** 2).mean().sqrt()`, `x.std()` | `5.0`, `2.0`, 약 `2.138`(계산값) | 표준편차. torch 기본 `std()`는 n-1로 나눠 조금 크다(05편 Bessel 보정의 다리) |
| F-M5-S2 | `r = torch.randn(10000)`, `r.mean()`, `r.std()`, `plt.hist(r.tolist(), 50)` | 약 0, 약 1, 종 모양 | 정규분포 |
| F-M5-S3 | `z = (x - x.mean()) / x.std()`, `z.mean()`, `z.std()` | 약 0, 약 1 | 표준화(04편 BatchNorm의 다리) |

| ID | 유형 | 묻는 것 | 정답 | 확인하는 것 |
|---|---|---|---|---|
| F-M5-Q1 | choice | 히스토그램 4장(종 모양 / 양 끝 -1, 1에 몰림 / 0에 몰림 / 넓게 퍼짐) 중 "tanh 포화"인 것 | 양 끝 몰림 | 그림 읽기(04편 핵심) |
| F-M5-Q2 | predict | `(torch.randn(10000) * 3).std()`는 대략 | 3 | 곱하면 퍼짐이 커진다(04편 초기화) |
| F-M5-Q3 | explain | 표준화하면 평균과 표준편차가 왜 0과 1이 되나 | 평균을 빼서 가운데가 0, 퍼짐으로 나눠 1 | 표준화의 뜻 |

#### F-M6 벡터와 행렬곱
- 목표: 내적(같은 자리끼리 곱해 모두 더하기), 행렬곱 모양 규칙 `(a, b) @ (b, c) = (a, c)`(가운데 숫자가 같아야 한다), 전치 `.T`(행과 열 바꾸기), 행렬곱이 "가중 합(비율대로 섞기)"이라는 뜻을 안다.

| ID | 치는 것 | 보이는 것 | 뜻 |
|---|---|---|---|
| F-M6-S1 | `w = torch.tensor([1., 2., 3.])`, `x = torch.tensor([4., 5., 6.])`, `(w * x).sum()`, `w @ x` | 둘 다 `32.` | 내적 = 곱해서 더하기(뉴런 하나) |
| F-M6-S2 | `A = torch.ones(2, 3)`, `B = torch.ones(3, 4)`, `(A @ B).shape`, `B @ A` | `torch.Size([2, 4])`, 모양 에러 | 가운데 숫자 규칙 |
| F-M6-S3 | `wei = torch.tensor([[1., 0.], [0.5, 0.5]])`, `v = torch.tensor([[10.], [20.]])`, `wei @ v` | `[[10.], [15.]]` | 둘째 행은 반반 섞기 = 평균(07편 attention의 다리) |

| ID | 유형 | 묻는 것 | 정답 | 확인하는 것 |
|---|---|---|---|---|
| F-M6-Q1 | predict | `(5, 2) @ (2, 7)`의 결과 모양 | `(5, 7)` | 모양 규칙 |
| F-M6-Q2 | choice | `(3, 4) @ (3, 4)`가 에러인 이유와 고치기 | 가운데 4와 3이 달라서. 뒤를 `.T`로 | 전치 |
| F-M6-Q3 | predict | `torch.tensor([1., 1.]) @ torch.tensor([2., 3.])` | 5 | 내적 |

**편 목표(`objectives`)**
- L01-O1: 입력을 조금 움직여 기울기를 숫자로 재고, 부호와 크기의 뜻을 말할 수 있다.
- L01-O2: `Value` 상자로 계산 그래프(어떤 값이 어떤 계산으로 만들어졌는지의 지도)를 만들고 그림으로 볼 수 있다.
- L01-O3: 연쇄법칙으로 기울기를 손으로 끝에서 앞으로 전달할 수 있다.
- L01-O4: 연산마다 `_backward`를 쓰고, 위상 정렬(앞 계산이 먼저 오게 줄 세우기)로 `backward()`를 자동으로 돌리고, `+=` 누적이 필요한 이유를 설명할 수 있다.
- L01-O5: `Neuron`, `Layer`, `MLP`를 만들고, 손실을 줄이는 학습 반복(앞으로 계산, 기울기 비우기, 뒤로 계산, 조금 고치기)을 돌릴 수 있다.
- L01-O6: 같은 계산을 PyTorch로 해서 기울기가 같은지 대조할 수 있다.

**셀 이름(이 편에서 계속 고치는 셀)**: Value 셀 = L01-S07, 예시 셀 = L01-S08, 뉴런 입력 셀 = L01-S23, 뉴런 계산 셀 = L01-S24, Neuron 셀 = L01-S42, Layer 셀 = L01-S44, MLP 셀 = L01-S45, 학습 셀 = L01-S52. Value 셀을 고친 단계는 모두 `rerun_first`에 Value 셀과 그 상자를 쓰는 셀을 넣습니다(클래스를 고친 뒤 옛 상자는 옛 설계도로 만든 것이라서).

### 5-2. 복습 설계

- **카드 만들기**: 한 편을 익힘 처리하면 그 편의 결과 예측·설명 문항, `must_pass` 문항, 재구성 조각에서 복습 카드를 만듭니다. 04편은 그림 읽기 문항 4개도 카드로 만듭니다. `kind`: predict → `predict`, explain과 choice → `concept`, fix_bug, apply, 재구성 → `hands_on`. ID는 `RC-{원본 id}-{번호}`.
- **카드 내용**: 원 문항과 같은 개념에 숫자나 예만 바꾼 변형. 번호마다 다른 변형을 써서 답을 외우지 않게 합니다.
- **간격**: data-spec 규칙(1, 3, 7, 14, 30, 그 뒤 60일. pass → 다음 간격, shaky → 같은 간격, miss → 1일). shaky는 H2 이상 힌트를 썼거나 맞혔지만 "헷갈렸어요"를 누른 경우.
- **하루 분량**: 25분 상한(data-spec). 카드 시간 어림: concept 1분, predict 2분, hands_on 6분.
- **언제 보이나**: 새 단계를 시작하기 전, 오늘 할 카드가 있으면 먼저 보여 줍니다(건너뛰기 가능, 기록됨).
- **revisit**: 한 편의 카드 절반 이상을 놓치면 그 편 상태를 `revisit`으로 바꾸고, 놓친 문항의 `after_step` 단계를 다시 하라고 권합니다.
- **카드 수**: L01 12, L02 9, L03 7, L04 11, L05 9, L06 8, L07 11, L08 6, L09 9, L10 11, 합계 93장.
