## 채점 셀과 결과코드

단계마다 코드 셀 바로 아래에 채점 셀이 있습니다. 채점 셀은 고치지 않고 실행만 합니다.

| 표시 | 뜻 |
|---|---|
| `✓ 맞음: …` | 통과 |
| `✕ 다시: …` | 다름. 무엇이 다른지와 고칠 곳이 쉬운 말로 나옵니다 |
| `· 건너뜀: …` | 채점할 수 없음(예: torch가 없음) |
| `⚠ 채점기 오류: …` | 채점 프로그램 자체의 고장(내 탓 아님) |
| `○ 아직: …` | 위 단계 셀을 아직 실행하지 않아 채점에 넘길 값이 없음. 또는 L01-R3에서 학습 셀을 다시 실행하는 중(기록하지 않음) |
| `○ 참고: …` | L01-R3에서 기준 안에 이미 통과한 모델을 더 학습한 뒤 다시 확인함(통과 기록은 그대로, 새로 기록하지 않음) |

맨 끝 "마무리" 셀을 실행하면 채점표와 결과코드가 나옵니다. 맨 아래 줄(`Z2H1.`로 시작)을 복사해 앱의 "결과코드 붙여넣기" 칸에 넣습니다.
재구성 구역의 결과(L01-R1~R3)도 같은 결과코드에 들어갑니다. 재구성을 아직 하지 않았으면 그 칸은 "아직 안 함"입니다.

### 채점 셀이 예외를 내지 않게 한 방식 (한 가지로 통일)

모든 채점 셀은 같은 모양입니다. 가운데 `check(...)` 줄은 `z2h_check/README.md`의 "1편 호출 규약" 표 그대로입니다.

```python
# 채점 셀: 고치지 말고 실행만 하세요.
try:
    check("L01-S04", Value)
except Exception as _err:
    _z2h_not_yet("L01-S04", _err)
```

- `check()`는 원래 예외를 내지 않습니다. 예외가 날 수 있는 곳은 `check()`에 넘길 값을 만드는 순간뿐입니다(아직 없는 이름 `Value`, `n` 등을 쓰면 NameError, `draw_dot(d)`가 실패하면 그 오류).
- 그때 `_z2h_not_yet`(준비 셀 맨 아래에 정의)이 "○ 아직: …" 한 줄만 출력합니다. 채점 기록은 남기지 않으므로 채점표에는 "아직 안 함"으로 나옵니다.
- 표와 다르게 부르는 칸 3개(정본 코드가 넘길 이름을 만들지 않아서)
  - L01-S02: 정본 셀은 숫자 기울기를 이름 없이 마지막 줄로 보여 줍니다. 채점 셀은 그 보여 준 값(IPython의 `Out` 기록 중 가장 최근 값)을 `_z2h_shown()`으로 넘깁니다. 준비 셀의 `___ = None` 때문에 IPython이 `_`를 더 이상 바꾸지 않아 `_` 대신 `Out`을 씁니다.
  - L01-S03: 정본 셀은 기울기를 print로만 보여 줍니다. 채점 셀은 셀이 만든 `d1`, `d2`, `h`로 `(d2 - d1) / h`를 다시 계산해 넘깁니다.
  - L01-S16: 눈으로 비교하는 단계라 `check("L01-S16", seen=True)`입니다. 빈 노트북에서 "맞음"이 나오지 않도록 학습 셀이 만든 `n`, `loss`가 있을 때만 부릅니다.

## 재구성(자기 확인) 구역

교사 결정(2026-11-17): 재구성 채점 노트북을 따로 만들지 않고, R1~R3는 이 노트북 끝에서 자기 확인으로 합니다. 확인 문제는 앱에서 11개 그대로입니다.
구역은 마무리 셀 바로 앞에 있고, 조각 id·순서·제목·과제 문구는 교사 정본 `rebuild_tasks` 그대로입니다.

| 셀 | 학생용 | 정답용 |
|---|---|---|
| 재구성 시작 | `_z2h_rebuild_start()` (같음) | 같음 |
| L01-R1 작업 셀 | 빈 셀 | 정본 L01-S04 셀을 L01-S10b까지 고친 Value 클래스(+ `import math`) |
| L01-R2 작업 셀 | 빈 셀 | 정본 L01-S04 셀을 L01-S11b까지 고친 Value 클래스(+ `import math`) |
| L01-R3 만들기 셀 | 빈 셀 | 정본 L01-S04 셀의 끝난 모습 + L01-S14 · S14b · S14c · S15 셀(+ `import math`, `import random`) |
| L01-R3 학습 셀 | 빈 셀 | 정본 L01-S15b 셀(20번 반복) |
| (정답용만) 학습 셀 다시 실행 2~5번째 | 없음 | 손실이 아직 0.1 위일 때만 학습 셀과 같은 코드를 한 번 더 |
| 자기 확인 셀(조각마다) | `check("L01-R1", Value)` 등 (같음) | 같음 |

정답 코드의 출처: 교사 힌트 H4("정답은 L01-S04, S05, S09b, S10, S10b 코드를 합친 것" 등)가 가리키는 정본 단계 코드를 그대로 합쳤습니다(새로 쓴 코드 없음, 원본은 karpathy/micrograd·nn-zero-to-hero, MIT). 셀 첫 줄 주석에 어느 단계 코드인지 적었습니다. `tests/reference_impl`의 기준 구현은 쓰지 않았습니다.

쓰는 법(학생)
1. 본문을 마친 뒤(다른 날이면 맨 위 준비 셀부터) "재구성 시작" 셀을 실행합니다. 위 본문에서 만든 이름(Value, n, math 같은 불러온 도구까지)을 지워 빈 노트북처럼 만듭니다. 채점 기록은 남습니다. 이 뒤로는 위 본문 셀을 다시 실행하지 않습니다.
2. 조각마다 빈 셀에 처음부터 다시 쓰고 실행한 뒤, 바로 아래 자기 확인 셀을 실행합니다. "재구성 시작" 셀을 건너뛰면 자기 확인 셀은 "○ 아직: 먼저 '재구성 시작' 셀을…"만 보입니다(본문 코드를 그대로 채점하지 않으려는 장치).
3. L01-R3: 만들기 셀 → 학습 셀(20번 반복) → 자기 확인 셀. 손실이 아직 0.1 위면 학습 셀만 다시 실행하고 자기 확인 셀도 다시 실행합니다.

L01-R3 다시 실행 규칙(숫자는 정본 `check.max_reruns` 5, `check.steps_per_run` 20, `check.max` 0.1에서 읽음)

| 자기 확인 결과 | 뜻 |
|---|---|
| `✓ 맞음: 학습 셀 k번째 실행(합계 20k번 반복)에서…` | 5번 안에 0.1 아래. 통과 |
| `○ 아직: … 앞으로 m번 더 됩니다` | 아직 0.1 위, 5번 전. 학습 셀을 한 번 더. 기록하지 않음(결과코드·서버·시도 횟수에 안 들어감) |
| `✕ 다시: 학습 셀 5번(합계 100번 반복) 실행해도…` | 구현을 의심하고 앱의 힌트 H1부터. 드물게 시작값 탓이면 만들기 셀부터 다시 |
| `✕ 다시: 학습 셀 6번째 실행…통과로 치지 않습니다…처음부터 다시 만들어 보세요` | 5번을 넘김. 만들기 셀부터 다시 실행하면 새 모델로 1번째부터 셉니다 |
| `○ 참고: 이 n 은 학습 셀 k번째 실행에서 이미 통과했습니다…` | 5번 안에 통과한 모델을 더 학습함. 통과 기록은 그대로 |

- 다시 실행한 횟수는 힌트로 세지 않습니다. 노트북은 힌트를 모르고, 결과코드 모양(`Z2H1.…`, JSON 칸 `v,l,p,f,t`)도 그대로입니다. 실행 횟수는 결과코드에 들어가지 않습니다.
- 몇 번째인지 세는 법: "재구성 시작" 셀이 IPython의 셀 실행 끝 알림에 작은 함수를 겁니다(`z2h_check.runs`). 셀이 끝날 때마다 이름 `n`의 모델 파라미터 값이 바뀌었으면 그 모델의 학습 셀 실행을 1 늘립니다. 그래서 자기 확인 셀을 건너뛰고 학습 셀만 여러 번 눌러도 횟수가 맞게 잡힙니다. 학습 셀 안의 반복 수(`range(20)`)는 보지 않습니다.
- Colab에서 이 세기가 되는지는 미확인입니다(맥 Jupyter 커널에서만 확인). 셀 수 없는 곳이면 "재구성 시작" 셀이 "손실만 봅니다"라고 알려 주고, 자기 확인은 손실 0.1 미만인지만 봅니다.
- 정답 구현의 실측(2026-11-17, 맥, 시작값 1000개, 정본 코드 그대로): 5번 안에 통과 999개(99.9%). 처음 통과한 번째는 1번째 815개, 2번째 172개, 3번째 8개, 4번째 2개, 5번째 2개. 남은 1개(시작값 578)는 6번째(120번 반복)에 0.1 아래로 내려갔습니다.
