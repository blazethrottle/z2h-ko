# 10 GPT-2 (124M) 재현: 축소판으로 전 과정 실습

- 영상: "Let's reproduce GPT-2 (124M)", 4시간 1분, https://youtu.be/l8pRSuU81PU (build-nanogpt README에서 확인)
- 원본 저장소: karpathy/build-nanogpt (`train_gpt2.py`, `fineweb.py`, `hellaswag.py`, `play.ipynb`, `input.txt`, 2026-11-16 파일 목록 확인). 원본 README에 따르면 커밋 기록이 단계별로 정리되어 있어 한 커밋씩 따라가기 좋습니다. 완성형 참고: karpathy/nanoGPT
- 원본 README가 적은 주의점(errata) 중 이 앱과 관련된 것: `torch.autocast`의 `device_type`에 장치 이름이 아니라 종류(`cuda`, `cpu` 등)를 넘겨야 하고, MPS는 이 부분 처리가 확실하지 않다고 적혀 있습니다. 이 앱은 MPS에서 autocast를 기본으로 끕니다. 맥미니 torch 2.15에서는 `device_type='mps'` autocast가 오류 없이 동작했지만 빨라지지 않아 선택으로만 둡니다(CTO 실측 2026-11-16, cto/MEASURE_M0.md).
- 영상 구간 타임스탬프와 커밋 대응: `research/10_gpt2_repro.md` 2절(유튜브 공식 챕터, build-nanogpt 커밋 해시) 기준으로 반영(2026-11-16). 3절 첫 표에 있습니다.

## 0. 이 편의 범위 결정(중요)

- 원본은 8×A100급 GPU로 약 100억 토큰(FineWeb-Edu)을 학습합니다. 이것은 유료 클라우드 GPU가 필요해 **얼큰이님 별도 승인 사항이며, 이 설계에 넣지 않습니다.**
- 이 앱의 기본은 **축소판**입니다. 원본의 모든 단계를 같은 코드 구조로 직접 해 보되, 모델 크기, 데이터 양, 학습 길이만 줄입니다.
- 실습 환경: 맥미니 M4 MPS 또는 Colab 무료 GPU(T4급). 둘 다 안 되는 기능(예: 여러 GPU 분산 학습)은 **개념 이해 + 코드 읽기**로 대신합니다.

| 원본 기능 | 맥미니 MPS | Colab 무료 GPU | 이 앱의 처리 |
|---|---|---|---|
| GPT-2 124M 공개 가중치로 생성 | 가능 | 가능 | 직접 실습 |
| 124M 모델 학습 몇 스텝 | 느리지만 가능 | 가능 | 직접 실습(짧게) |
| TF32 | 해당 없음 | 하드웨어 따라 다름 | 개념 + 설정 한 줄 체험 |
| bf16·fp16 autocast | 오류 없이 되지만 빨라지지 않음(스텝 0.233초 → 0.238초, CTO 실측 2026-11-16, cto/MEASURE_M0.md) | T4는 bf16 하드웨어 지원이 없어 fp16 사용(Colab 실측 아님) | 선택. 기본은 끔 |
| torch.compile | 됨, 약 8% 빠름(첫 스텝 약 4.9초 컴파일, CTO 실측 2026-11-16, cto/MEASURE_M0.md) | 가능(실측 아님) | 선택. 기본은 끔 |
| fused AdamW | 됨, 약 4% 빠름(CTO 실측 2026-11-16, cto/MEASURE_M0.md) | 가능(실측 아님) | 선택. 기본은 끔 |
| Flash attention(`F.scaled_dot_product_attention`) | 가능 | 가능 | 직접 실습 |
| 기울기 누적 | 가능 | 가능 | 직접 실습 |
| DDP(여러 GPU) | 불가 | 불가(1개) | 개념 + 코드 읽기 |
| FineWeb-Edu 100억 토큰 | 불가 | 불가 | 필요한 만큼만(1천만~2천만 토큰) 받거나 tiny shakespeare. 2.15GB parquet 파일은 받지 않음 |
| HellaSwag 평가 | 일부 문항 가능 | 가능 | 일부 문항(예: 200개)으로 실습 |

## 1. 학습 목표

1. Hugging Face 이름 규칙에 맞춘 GPT-2 클래스(`wte`, `wpe`, `h`(블록들), `ln_f`, `lm_head`)를 07편 지식으로 직접 쓰고, 공개 124M 가중치를 불러와 글을 생성할 수 있습니다.
2. 무작위 초기화 모델을 tiktoken GPT-2 토큰으로 학습시키는 전 과정(데이터 로더, AdamW, 손실 확인)을 돌리고, 시작 손실이 약 -ln(1/50257) ≈ 10.8 근처여야 하는 이유를 설명할 수 있습니다.
3. 가중치 공유(입력 임베딩과 출력층이 같은 표를 쓰기)와 GPT-2식 초기화(표준편차 0.02, 잔차 쪽 투영은 층 수에 맞춰 더 작게)를 설명하고 적용할 수 있습니다.
4. 속도 개선 기법(정밀도 낮추기, 컴파일, flash attention, "보기 좋은 숫자" 어휘 50304)이 각각 무엇을 바꾸는지 말하고, 내 장비에서 1~2개를 측정해 비교할 수 있습니다.
5. GPT-3 논문식 학습 설정(AdamW 베타·eps, 기울기 자르기, 워밍업 + 코사인 학습률, 가중치 감쇠, 기울기 누적)을 코드로 넣고 그 이유를 설명할 수 있습니다.
6. 검증 손실과 HellaSwag(문장 뒤에 올 가장 그럴듯한 끝을 고르는 시험) 일부 문항으로 모델을 평가하고, 원본 규모와 축소판 결과 차이를 해석할 수 있습니다.

- 입력: `next_batch()`: 현재 위치에서 B*T+1개를 잘라 x, y로 나누고 위치를 옮기며, 끝에 가면 처음으로 돌아가기. 학습 반복에 연결.
- 보여야 하는 것: 손실이 서서히 내려감(외우기가 아닌 학습).
- 뜻: 매번 다른 조각을 보므로 S07의 외우기와 다릅니다.

**L10-S09 가중치 공유**
- 새 코드: 1줄
- 입력: `self.transformer.wte.weight = self.lm_head.weight`
- 보여야 하는 것: 파라미터 수가 약 3,800만 개(50257×768) 줄어듦.
- 뜻: 입력에서 "비슷한 토큰"과 출력에서 "비슷한 토큰"은 같아야 한다는 생각입니다.

**L10-S09b GPT-2식 초기화 (긴 단계)**
- 새 코드: 약 9줄 (긴 단계: 나누면 뜻이 끊겨 한 단계로 둡니다. 줄마다 한국어 풀이가 붙습니다)
- 입력: `_init_weights`에서 Linear는 표준편차 0.02, 잔차로 들어가는 투영층(`NANOGPT_SCALE_INIT` 표시)은 `0.02 * (2 * n_layer) ** -0.5`, 임베딩도 0.02. `self.apply(self._init_weights)`.
- 보여야 하는 것: 시작 손실이 여전히 약 10.8 근처.
- 뜻: 잔차가 쌓일 때 값이 커지지 않게 줄입니다.

**L10-S10 시간 재기와 속도 개선 체험 (긴 단계)**
- 새 코드: 약 10줄 (긴 단계: 나누면 뜻이 끊겨 한 단계로 둡니다. 줄마다 한국어 풀이가 붙습니다)
- 입력: 스텝마다 걸린 시간(ms)과 초당 토큰 수 출력. 이어서 장비별로 가능한 것만 하나씩 켜고 비교: 
  - Colab: `torch.set_float32_matmul_precision('high')`(TF32, 지원 GPU에서만), `torch.autocast(device_type='cuda', dtype=torch.float16)`, `torch.compile(model)`.
  - 맥미니: 기본은 끈 상태로 측정합니다. 선택으로 켜 볼 수 있는 것: `torch.autocast(device_type='mps', dtype=torch.bfloat16)`(오류는 없지만 빨라지지 않음), `torch.compile(model)`(약 8% 빠름), fused AdamW(약 4% 빠름)(CTO 실측 2026-11-16, cto/MEASURE_M0.md). flash attention은 모두 공통. Colab 쪽 효과는 아직 실측하지 않았습니다.
- 보여야 하는 것: 켜기 전후 초당 토큰 수 표. 내 장비에서 효과가 작거나 없으면 정상입니다. 리서치 제안대로 영상의 스텝당 시간 변화(A100 1장 기준 약 1000ms → TF32 333ms → bfloat16 300ms → compile 130ms → flash attention 96ms → 50304 93ms, research/10 2절 챕터 제목)를 "영상 수치 읽기" 표로 함께 봅니다.
- 뜻: 같은 계산을 덜 정밀한 숫자로, 메모리 이동을 줄여서 빠르게 합니다. 장비마다 효과가 다릅니다.

**L10-S11 flash attention과 보기 좋은 숫자**
- 입력: Head 계산 4줄(점수, 마스크, softmax, 가중합)을 `F.scaled_dot_product_attention(q, k, v, is_causal=True)` 한 줄로 바꾸기. `vocab_size=50304`로 바꿔 시간 비교.
- 보여야 하는 것: 결과 손실은 비슷, 시간은 같거나 짧아짐.
- 뜻: 50304는 2의 거듭제곱(128)으로 잘 나누어져 GPU 계산이 효율적입니다. 추가된 토큰은 쓰이지 않아 확률이 0 쪽으로 학습됩니다.

**L10-S12 AdamW 설정과 기울기 자르기**
- 새 코드: 약 3줄
- 입력: AdamW `betas=(0.9, 0.95), eps=1e-8`, 역전파 뒤 `norm = torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)`(기울기 크기 상한), norm 출력.
- 보여야 하는 것: 스텝마다 norm 출력.
- 뜻: 가끔 튀는 큰 기울기가 모델을 망가뜨리지 않게 막습니다.

**L10-S12b 학습률 일정 get_lr (긴 단계)**
- 새 코드: 약 10줄 (긴 단계: 나누면 뜻이 끊겨 한 단계로 둡니다. 줄마다 한국어 풀이가 붙습니다)
- 입력: `get_lr(it)`: 워밍업 동안 직선으로 올리고 그 뒤 코사인 곡선으로 최소값까지 내리기. 반복마다 optimizer의 lr에 넣기, 그래프 그리기.
- 보여야 하는 것: 학습률 그래프(올라갔다 부드럽게 내려가는 곡선).
- 뜻: 처음엔 조심스럽게, 중간엔 힘차게, 끝엔 섬세하게 걷는 일정입니다.

**L10-S12c configure_optimizers와 weight decay (긴 단계)**
- 새 코드: 약 10줄 (긴 단계: 나누면 뜻이 끊겨 한 단계로 둡니다. 줄마다 한국어 풀이가 붙습니다)
- 입력: `configure_optimizers`: 2차원 이상 가중치에만 weight decay 0.1, 나머지(편향, LayerNorm)는 0. 묶음별 개수 출력. fused AdamW는 원본에서는 CUDA일 때만 켜지만, 맥미니 MPS에서도 동작하고 약 4% 빠릅니다(CTO 실측 2026-11-16, cto/MEASURE_M0.md). 앱에서는 선택 칸으로 둡니다.
- 보여야 하는 것: decay 묶음과 no-decay 묶음의 텐서 수와 파라미터 수.
- 뜻: 큰 가중치를 조금씩 작게 당기는 힘(가중치 감쇠)을 필요한 곳에만 씁니다.

**L10-S13 기울기 누적 (긴 단계)**
- 새 코드: 약 10줄 (긴 단계: 나누면 뜻이 끊겨 한 단계로 둡니다. 줄마다 한국어 풀이가 붙습니다)
- 입력: `total_batch_size`(축소판 기본 예: 2^15 = 32,768 토큰)와 `grad_accum_steps = total_batch_size // (B*T)`. 작은 배치마다 `loss = loss / grad_accum_steps; loss.backward()`, 모은 뒤 한 번 `step()`.
- 보여야 하는 것: 작은 배치로도 큰 배치와 같은 효과를 내는 학습 로그.
- 뜻: 원본은 약 50만 토큰 배치를 씁니다. 메모리가 작으면 여러 번 나눠 기울기를 더한 뒤 한 번 걷습니다. 나누기를 빼먹는 버그는 Q07.

**L10-S14 DDP 읽기(코드 실행 없음)**
- 입력: 원본 `train_gpt2.py`의 DDP 부분을 앱의 줄별 풀이와 함께 읽기.
- 뜻: GPU 8개가 각자 다른 데이터 조각을 보고, 기울기를 평균 내어 함께 걷습니다. 우리 장비엔 1개뿐이라 `ddp_world_size = 1`인 경우로 돌립니다. 원본 코드 주석도 DDP는 CUDA가 필요하다고 적고 있고, fused AdamW도 CUDA에서만 켜집니다(research/10 6절).

**L10-S15 데이터: FineWeb-Edu 작은 조각**
- 입력: 원본 `fineweb.py`의 구조(내려받기, 토큰화, 1억 토큰 단위 조각 파일 저장, 첫 조각은 검증용)를 읽고, 앱 축소 설정으로 아주 작은 일부만 받아 조각 1~2개 만들기. 받는 양은 본 학습에 필요한 만큼만입니다: 기본 설정(S16) 1000스텝 × 16,384토큰 = 약 1,640만 토큰(문서 약 1만 5천 개, 텍스트 약 76MB), 빠른 대안 500스텝이면 약 820만 토큰이라 1천만 토큰(문서 약 9,450개, 텍스트 약 46MB, uint16 조각 약 20MB)이면 충분합니다(CTO 실측 2026-11-16, cto/MEASURE_M0.md의 환산). parquet 파일 하나(약 2.15GB)나 전체 sample-10BT(28.5GB)는 받지 않고, Hugging Face datasets-server rows API로 앞부분 문서만 받습니다(요청 한도는 미확인). 받기 어려우면 tiny shakespeare로 대신.
- 보여야 하는 것: `.npy` 조각 파일과 토큰 수.
- 뜻: 문서마다 앞에 `<|endoftext|>`(09편 특수 토큰)를 붙여 경계를 표시합니다. 원본 전체는 조각 100개, 저장 용량 약 20GB(리서치 계산값)라 전부 받지 않습니다. 축소 크기는 위 환산값을 씁니다. 마지막 조각에서 멈추는 보고(build-nanogpt#25)가 있어 앱은 조각 수를 정해 두고 중단합니다.

**L10-S16 축소판 본 학습 (긴 단계)**
- 새 코드: 약 8줄 (긴 단계: 나누면 뜻이 끊겨 한 단계로 둡니다. 줄마다 한국어 풀이가 붙습니다)
- 입력: 앱 기본 축소 설정 학습: n_layer 6, n_head 6, n_embd 384, block_size 256, vocab 50304, B 8, T 256, 한 스텝 16,384토큰(2^14, 기울기 누적 8), **1000스텝**. 파라미터는 임베딩을 빼면 약 1,060만, 포함하면 약 3,010만입니다. 일정 간격으로 val 손실과 생성 샘플 출력, 체크포인트 저장.
  - 시간(맥미니 M4 MPS): 한 스텝 32,768토큰 설정이 스텝당 3.60초로 실측되었고(CTO 실측 2026-11-16, cto/MEASURE_M0.md), 토큰을 절반으로 줄인 기본 설정은 스텝당 약 1.8초로 1000스텝 약 30분입니다(절반 줄이면 시간도 절반이라는 가정, 중간 평가로 10~20% 더 걸릴 수 있음).
  - 빠른 대안: 같은 설정으로 500스텝(약 15분). 참고로 32,768토큰 그대로 500스텝도 약 30분입니다.
  - 실측 참고값: 32,768토큰 설정 200스텝에서 손실 10.88 → 4.70.
- 보여야 하는 것: train, val 손실이 함께 내려가는 그래프, 생성 글이 점점 문장다워짐.
- 뜻: 원본과 같은 과정을 작게 끝까지 돌렸습니다. 최종 손실 목표값은 기본 설정 1000스텝 실측 뒤 앱에 표시합니다(현재는 '시작 약 10.8에서 확실히 내려감'으로 판정).

**L10-S17 HellaSwag 일부 평가 (긴 단계)**
- 새 코드: 약 10줄 (긴 단계: 나누면 뜻이 끊겨 한 단계로 둡니다. 줄마다 한국어 풀이가 붙습니다)
- 입력: 원본 `hellaswag.py` 구조를 따라, 공개 GPT-2 124M과 내 축소 모델을 앞 200문항으로 평가. 각 보기 끝맺음의 평균 손실이 가장 낮은 것을 고름.
- 보여야 하는 것: 두 정확도. 무작위로 고르면 약 25%(보기 4개).
- 뜻: 내 작은 모델은 25% 근처일 것입니다. 기준값(hellaswag.py 전체 10,042문항): 공개 GPT-2 124M acc_norm 0.2955, 영상의 40B 토큰 학습 결과 약 33%(research/10 6절). 200문항 일부라 숫자가 흔들릴 수 있습니다.

**L10-S18 정리: 다음 단계**
- 입력: 앱 요약 읽기.
- 뜻: 이 모델은 문서를 이어 쓰는 기본 모델입니다. 비서로 만들려면 08편의 미세조정 단계가 필요하며, 원본 규모 재현은 유료 GPU라 별도 승인 뒤 선택 과정으로만 둡니다.

## 7. 자주 막히는 곳

리서치 반영(`research/10_gpt2_repro.md` 5절, GitHub 이슈·Discussions·유튜브 댓글 근거):
- `GPT.from_pretrained('gpt2')`에서 가중치 파일을 못 찾는 OSError(build-nanogpt#103). 인터넷 연결과 Hugging Face 캐시를 먼저 봅니다.
- `unsupported autocast device_type 'cuda:0'`(#44, 원본 정오표와 같은 문제). Q10과 같습니다.
- OpenAI 가중치 일부를 전치해야 하는 이유(TensorFlow Conv1D에서 온 형식, 자막 0:30:00 부근 댓글). S03 풀이에 넣습니다.
- flash attention으로 바꾼 뒤 마스크가 사라진 것처럼 보임: `is_causal=True`가 마스크 역할(Discussions #65).
