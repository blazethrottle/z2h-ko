## 4. 비개발자를 위한 설계 원칙

1. **코드 한 줄마다 한국어 풀이를 붙입니다.** 줄 끝에 `# 풀이`가 오거나, 코드 바로 아래 표로 줄별 설명을 붙입니다. 풀이 없는 코드는 앱에 내보내지 않습니다.
2. **한 번에 한 걸음.** 한 단계에서 새로 치는 코드는 1~5줄입니다. 예외로, 나누면 뜻이 끊기는 경우(예: 클래스 뼈대, 식과 확인이 짝인 블록)에는 10줄까지 한 단계로 두고 단계 제목에 "(긴 단계)"를 붙입니다. 긴 단계도 모든 줄에 한국어 풀이가 붙습니다. 10줄을 넘는 단계는 두지 않고 나눕니다(기존 아이디는 그대로 두고 뒤 조각에 `b`, `c`를 붙임, 예: L01-S14, L01-S14b, L01-S14c). 새 개념은 한 단계에 하나만 들어갑니다.
   - 준비 코드 규칙: 그림 그리기처럼 학습 목표가 아닌 도구 코드(예: L01-S06의 `draw_dot`)는 "준비 코드"로 붙여 넣기만 합니다. 줄 수 규칙에 넣지 않지만 줄별 풀이는 펼쳐 볼 수 있게 두고, 확인 문제와 재구성 과제에는 내지 않습니다.
   - 줄 수는 원본 구현을 기준으로 한 교사 몽키의 추정("약 N줄")이며, 콘텐츠 제작 때 실제 코드로 다시 셉니다.
   - 각 편 "익혔다" 기준의 "S01~Sxx 완료"는 그 사이의 쪼갠 단계(b, c)도 포함합니다. 쪼갠 단계는 원래 단계의 영상 구간을 그대로 쓰고, 같은 챕터를 쓰는 단계들은 같은 구간을 공유합니다(video-segments.json의 `shared_with`).
3. **실행하고 확인하기.** 모든 단계는 "입력할 것 → 보여야 하는 것 → 그 뜻" 세 칸으로 씁니다. 보여야 하는 것이 다르면 바로 힌트로 연결합니다.
4. **아는 것을 가정하지 않습니다.** 전문 용어는 처음 나올 때 괄호 안에 쉬운 말로 풉니다. 예: 기울기(gradient, 값을 조금 바꿨을 때 결과가 얼마나 바뀌는지).
5. **예측 먼저.** 실행 전에 "무엇이 나올 것 같나요?"를 묻고, 실행 뒤에 맞춰 봅니다. 틀려도 감점하지 않고 그 차이를 설명합니다.
6. **원본을 존중하되 통째로 베끼지 않습니다.** 원본 저장소(karpathy/micrograd, makemore, nn-zero-to-hero, nanoGPT, minbpe, build-nanogpt)는 이름과 파일 위치로 안내하고, 단계별로 필요한 짧은 조각만 직접 쳐 보게 합니다. 정답 대조는 원본 저장소 파일과 비교하는 방식입니다.
7. **틀려도 괜찮은 구조.** 에러는 실패가 아니라 단서로 다룹니다. 에러 메시지 읽기(F-P7)를 1편 전에 꼭 익힙니다.
8. **스스로 다시 만들기로 익힘을 판정합니다.** 문제만 맞히는 것으로는 "익혔다"가 아닙니다. 편마다 핵심 조각을 힌트를 적게 써서 다시 만들어야 합니다.
9. **장비 현실에 맞춥니다.** 맥미니 M4의 MPS(애플 칩의 GPU 가속) 또는 무료 Colab만 씁니다. 10편은 축소판이 기본이며, 원본 규모(유료 GPU)는 얼큰이님 별도 승인 사항이라 설계에 넣지 않습니다.
10. **문장 규칙.** 합니다체, 쉬운 말, 긴 줄표 기호는 쓰지 않습니다.
