## 1. 학습 목표

1. 토큰화(tokenization, 글을 모델이 다룰 조각 번호로 바꾸는 일)가 왜 필요하고, LLM(대형 언어 모델)의 이상한 행동 여럿이 왜 토큰화에서 오는지 예로 설명할 수 있습니다.
2. 유니코드(Unicode, 세계 모든 글자에 번호를 붙인 표)와 UTF-8(그 번호를 1~4바이트로 저장하는 방식)의 차이를 말하고, 한글 한 글자가 몇 바이트인지 확인할 수 있습니다.
3. BPE(Byte Pair Encoding, 가장 자주 나오는 이웃 쌍을 새 토큰 하나로 합치기를 반복하는 방법)를 `get_stats`, `merge`로 직접 구현하고 학습시킬 수 있습니다.
4. `encode`, `decode`를 구현하고, 아무 글이나 encode 후 decode하면 원래 글이 나오는지 확인할 수 있습니다.
5. GPT-2의 정규식(regex, 글을 규칙에 따라 자르는 패턴) 사전 분할과 특수 토큰(예: `<|endoftext|>`)의 역할을 설명하고, minbpe의 RegexTokenizer 결과를 tiktoken과 비교할 수 있습니다.
6. 어휘 크기(vocab size)를 키우고 줄일 때의 장단점을 설명할 수 있습니다.

## 2. 선행 지식

- 반드시: F-P3(사전), F-P4(반복, zip), F-P5, F-P6(클래스 상속은 이 편에서 처음 풀이), 07편(토큰, 임베딩 표 크기)
- 있으면 좋음: F-P7(에러 읽기)

**L09-S01 토크나이저 놀이터에서 보기**
- 입력: 앱이 안내하는 공개 토큰 시각화 웹(예: tiktokenizer)에서 영어 문장, 한국어 문장, 숫자, 파이썬 코드를 붙여 넣기.
- 보여야 하는 것: 영어보다 한국어가 같은 뜻에 토큰을 더 많이 씀, 숫자가 이상하게 잘림, 공백 하나하나가 토큰이 되기도 함.
- 뜻: 모델은 글자가 아니라 이 조각들을 봅니다.

**L09-S02 유니코드 번호와 UTF-8 바이트**
- 입력: `ord("안")`, `list("안녕".encode("utf-8"))`, `len("hello".encode("utf-8"))`.
- 보여야 하는 것: 큰 번호 하나, 바이트 6개(한글 한 글자 3바이트), 5.
- 뜻: 바이트는 0~255라 토큰 256개로 모든 글을 쓸 수 있지만 너무 길어집니다. 그래서 합치기(BPE)를 합니다.

**L09-S03 get_stats: 이웃 쌍 세기**
- 입력:
  ```python
  def get_stats(ids):                       # ids: 숫자 목록
      counts = {}                           # 쌍 → 횟수 사전
      for pair in zip(ids, ids[1:]):        # 이웃한 두 개씩 짝짓기(F-P4)
          counts[pair] = counts.get(pair, 0) + 1   # 없으면 0에서 시작해 1 더하기
      return counts
  ```
- 보여야 하는 것: `get_stats([1,2,3,1,2])` → `{(1,2): 2, (2,3): 1, (3,1): 1}`
- 뜻: 가장 많이 나온 쌍이 다음에 합칠 후보입니다.

**L09-S04 merge: 쌍을 새 번호로 바꾸기**
- 입력: `merge(ids, pair, idx)`: 목록을 앞에서부터 보며 pair가 나오면 idx 하나로 바꾸고 두 칸 건너뛰기.
- 보여야 하는 것: `merge([5,6,6,7,9,1], (6,7), 99)` → `[5,6,99,9,1]`
- 뜻: 합칠 때마다 목록이 짧아집니다.

**L09-S05 BPE 학습 반복**
- 입력: 긴 영어 글을 UTF-8 바이트로 바꾸고, `vocab_size = 276`이면 20번(276-256) 반복: get_stats → 최다 쌍 → `merge` → `merges[pair] = idx` 기록.
- 보여야 하는 것: 길이가 줄어든 정도(압축률) 출력, 첫 합치기 쌍이 흔한 글자 쌍(예: 'e'와 공백).
- 뜻: merges 사전이 토크나이저가 "배운 것" 전부입니다.

**L09-S06 decode**
- 입력: `vocab = {i: bytes([i]) for i in range(256)}` 후 merges 순서대로 `vocab[idx] = vocab[p0] + vocab[p1]`, decode는 바이트를 이어 붙여 `.decode("utf-8", errors="replace")`.
- 보여야 하는 것: 원래 글.
- 뜻: `errors="replace"`가 없으면 잘못된 바이트 조합에서 에러가 납니다(Q05).

**L09-S07 encode**
- 입력: 글을 바이트로 바꾼 뒤, 지금 목록의 쌍 중 merges에서 가장 먼저 배운(번호가 가장 작은) 쌍을 계속 합치기. 합칠 쌍이 없으면 멈춤.
- 보여야 하는 것: `decode(encode(text)) == text` 가 True(학습에 안 쓴 글로도).
- 뜻: 학습 때와 같은 순서로 합쳐야 같은 결과가 나옵니다.

**L09-S08 GPT-2 정규식 분할**
- 입력: `import regex as re`, GPT-2 분할 패턴(minbpe `regex.py`의 `GPT2_SPLIT_PATTERN`)으로 `re.findall(pattern, "Hello've world123 how's are you!!!?")`.
- 보여야 하는 것: 단어, 숫자, 축약형('ve, 's), 문장 부호가 따로 나뉜 목록.
- 뜻: 덩어리 경계를 넘어서는 합치기를 막아 "dog."와 "dog!"가 서로 다른 토큰이 되는 낭비를 줄입니다.

**L09-S09 tiktoken과 비교**
- 입력: `import tiktoken; enc = tiktoken.get_encoding("gpt2")` 와 `"cl100k_base"`(GPT-4)로 같은 글 encode 비교. 공백 여러 칸이 든 파이썬 코드로도 비교.
- 보여야 하는 것: GPT-4 쪽이 토큰 수가 적고, 공백 묶음이 한 토큰이 됨.
- 뜻: 어휘가 커지고 규칙이 바뀌면 같은 글을 더 짧게 표현합니다.

**L09-S10 minbpe로 정리**
- 입력: minbpe를 내려받아 `BasicTokenizer`, `RegexTokenizer`로 README 빠른 시작 예(`"aaabdaaabac"`, 256+3) 실행, 이어서 `GPT4Tokenizer` 결과를 tiktoken과 비교.
- 보여야 하는 것: README와 같은 `[258, 100, 258, 97, 99]`, GPT4Tokenizer와 tiktoken의 결과 일치.
- 뜻: 우리가 만든 것이 실제 GPT-4 토크나이저와 같은 원리입니다. 클래스 상속(base.py의 `Tokenizer`를 물려받기)은 여기서 처음 풀이합니다.

**L09-S11 특수 토큰**
- 입력: `enc.encode("<|endoftext|>", allowed_special="all")`
- 보여야 하는 것: 번호 하나(gpt2 기준 50256).
- 뜻: 문서 끝 같은 신호는 합치기로 만들지 않고 따로 정한 번호를 씁니다. 10편 데이터 준비에서 다시 씁니다.

**L09-S12 이상한 행동의 원인 찾기(이해 활동)**
- 할 것: 앱 카드 6장을 보고 원인 짝짓기: 철자 거꾸로 쓰기가 서툼, 간단한 산수 실수, 한국어가 비싸고 느림, 코드 들여쓰기 처리, 특정 이상한 단어(예: SolidGoldMagikarp)에서 엉뚱한 반응, 문장 끝 공백 경고.
- 뜻: 모두 "모델은 글자가 아니라 토큰을 본다"로 설명됩니다.

**L09-S13 sentencepiece와 어휘 크기 이야기(읽기 중심)**
- 입력(선택): `sentencepiece`로 작은 모델을 학습해 결과 보기.
- 뜻: Llama 계열이 쓰는 다른 방식입니다. 어휘가 크면 글이 짧아지지만 임베딩·출력 표가 커지고 드문 토큰은 덜 배웁니다.

## 7. 자주 막히는 곳

리서치 반영(`research/09_gpt_tokenizer.md` 5절, GitHub 이슈와 유튜브 댓글 근거):
- 같은 토큰이 연속 반복(1,1,1,1)되면 쌍 개수가 실제로 합칠 수 있는 수보다 많게 세어짐(minbpe#51). Q02와 함께 "세기와 합치기는 다를 수 있다"를 풀이합니다.
- 빈 문자열이나 공백만 있는 입력에서 `max() arg is an empty sequence`(minbpe#114). S07 encode에 "합칠 쌍이 없으면 멈춤" 조건이 필요한 이유입니다.
- GPT 정규식이 결합 문자가 있는 언어를 음절 중간에서 끊고, 영어 외 언어가 불리함(minbpe#73, #92). Q10과 이어집니다.
- 순수 파이썬 학습이 느림(minbpe#5, #25). 학습 글 크기를 작게 잡습니다.
- 길어서 앞부분을 잊음(댓글). 앱은 이 편을 S01~S07, S08~S11, S12~S13 세 묶음으로 나눠 묶음마다 짧은 점검을 둡니다.
- 리서치 제안: 0:18:15 UTF-8 구간에서 한글 3바이트 직접 확인(S02에 반영). 3바이트는 UTF-8 표준 지식이며 영상 발화로 확인한 것은 아닙니다.

교사 몽키 예상(강의 지식 기반):
- 바이트와 글자의 차이. 한글 예(3바이트)로 먼저 봅니다.
- encode의 "가장 먼저 배운 쌍" 고르기(`min`과 `key=lambda` 조합). F-P5의 lambda로 돌아갑니다.
- 정규식 패턴 자체는 읽기 어려움. 패턴을 외우지 않고 결과만 해석하게 합니다.
- `regex` 라이브러리와 기본 `re`의 차이(설치 필요).
- 클래스 상속(base.py). 앱에서 "부모 설계도를 물려받아 일부만 바꾸기"로 풀이합니다.

## 8. 편별 힌트 예시

- S07: H1 "지금 목록의 쌍 중 어느 것을 먼저 합쳐야 학습 때와 같아질까요?" / H2 "merges의 번호가 가장 작은 쌍. `min(stats, key=lambda p: merges.get(p, float('inf')))`" / H3 빈칸 두 개 코드.
- Q04: H1 "바이트 토큰은 몇 개로 시작하나요?" / H2 "300 - 256".
