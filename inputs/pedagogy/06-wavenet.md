## 1. 학습 목표

1. 4편의 층 클래스에 `Embedding`, `FlattenConsecutive`, `Sequential`을 더해 torch.nn과 같은 모양으로 코드를 정리할 수 있습니다.
2. 문맥을 8글자로 늘리고, 글자를 한꺼번에 펴는 대신 2개씩 단계적으로 합치는 계층(나무 모양) 구조를 만들 수 있습니다.
3. 층을 지날 때마다 텐서 모양을 예측하고 출력해 확인할 수 있습니다.
4. 3차원 입력에서 BatchNorm1d가 잘못된 축으로 평균을 내던 버그를 찾아 고칠 수 있습니다.
5. 이 구조가 WaveNet의 팽창 인과 합성곱(dilated causal convolution, 간격을 띄워 과거만 보는 필터)과 어떤 관계인지 개념 수준으로 설명할 수 있습니다.

**L06-S01 출발 코드 정리**
- 입력: 4편 층 클래스 코드 실행, 학습 손실 그래프를 `torch.tensor(lossi).view(-1, 1000).mean(1)`로 1000개씩 평균 내어 그리기.
- 보여야 하는 것: 덜 흔들리는 매끈한 손실 곡선.
- 뜻: 흔들리는 미니배치 손실을 구간 평균으로 보기 쉽게 만들었습니다.

**L06-S02 Embedding과 Flatten 층**
- 입력: `Embedding(num, dim)`(C 표를 품은 층), `Flatten()`(view로 펴는 층) 클래스를 만들고 층 리스트 맨 앞에 넣기.
- 보여야 하는 것: 학습 결과가 이전과 같음.
- 뜻: 임베딩도 층 하나로 다룹니다.

**L06-S03 Sequential**
- 입력: 층 리스트를 받아 차례로 부르는 `Sequential(layers)` 클래스, `model = Sequential([...])`, `model(Xb)`.
- 보여야 하는 것: 같은 결과, 코드가 짧아짐.
- 뜻: torch.nn.Sequential과 같은 생각입니다.

**L06-S04 평가 모드 버그**
- 입력: 평가 전 모든 층의 `training = False` 설정을 빼먹고 손실을 보기.
- 보여야 하는 것: 이상하게 흔들리는 dev 손실, 다시 설정하면 정상.
- 뜻: BatchNorm은 학습과 평가에서 다르게 동작합니다(4편 S08).

**L06-S05 문맥 8글자로**
- 입력: `block_size = 8`로 데이터 다시 만들고 기존 구조(한꺼번에 펴기)로 학습.
- 보여야 하는 것: dev 손실이 조금 좋아짐.
- 뜻: 더 많이 보면 낫지만, 8글자를 한 번에 눌러 담는 것은 비효율적입니다.

**L06-S06 모양 하나씩 찍어 보기**
- 입력: 배치 4개로 `for layer in model.layers: print(layer.__class__.__name__, tuple(layer.out.shape))`.
- 보여야 하는 것: Embedding [4,8,10], Flatten [4,80], Linear [4,200] ...
- 뜻: 모양 추적은 이 편의 핵심 기술입니다.

**L06-S07 FlattenConsecutive(2개씩 합치기)**
- 입력: [B, T, C]를 [B, T/n, C*n]으로 바꾸는 층. n=2. T가 1이 되면 가운데 축을 없앰(squeeze).
- 보여야 하는 것: [4,8,10] → [4,4,20] → (Linear) [4,4,200] → [4,2,400] ...
- 뜻: 이웃한 두 글자 → 두 쌍 → 네 쌍 식으로 나무처럼 합칩니다.

**L06-S08 Linear가 3차원 입력에도 되는 이유**
- 입력: `(torch.randn(4, 5, 80) @ torch.randn(80, 200)).shape`
- 보여야 하는 것: [4, 5, 200]
- 뜻: 행렬곱은 마지막 축에만 작용하고 앞 축들은 묶음(batch)처럼 다룹니다.

**L06-S09 BatchNorm 3차원 버그 고치기**
- 입력: BatchNorm1d에서 입력이 3차원이면 `dim = (0, 1)`로 평균·분산 내기.
- 보여야 하는 것: running_mean 모양이 [1,1,채널]로 맞고, dev 손실이 조금 좋아짐.
- 뜻: 고치기 전에는 위치마다 따로 통계를 내고 있었습니다. 에러 없이 조용히 틀리는 버그였습니다.

**L06-S10 모델 키우기**
- 입력: 임베딩 24, 은닉 128 정도로 키워 학습(시간이 걸리면 MPS나 Colab GPU 사용).
- 보여야 하는 것: dev 손실이 이 편 시작 때보다 낮아짐. 영상 마지막에 Karpathy가 말하는 손실은 1.993입니다(research/06, 자막 0:55:30). 내 결과는 이 근처 범위로 비교합니다.
- 뜻: 구조를 바꾸고 키우면 성능이 오릅니다. 하지만 실험이 오래 걸립니다.

**L06-S11 합성곱과의 관계 읽기(코드 없음)**
- 입력: 앱의 그림 설명 읽기.
- 보여야 하는 것: 없음(이해 문제).
- 뜻: 우리 코드는 위치마다 따로 계산하지만, 합성곱은 같은 작은 층을 위치를 밀며 한 번에 재사용해 효율적으로 계산합니다. 원본 노트북도 합성곱 구현은 다루지 않습니다.

## 7. 자주 막히는 곳

리서치 반영(`research/06_wavenet.md` 5절, GitHub 이슈와 유튜브 댓글 근거):
- FlattenConsecutive를 3개 넘게 쌓으면 `not enough values to unpack (expected 3, got 2)`(nn-zero-to-hero#23). T가 1이 되어 squeeze된 뒤라서입니다. S07 힌트에 넣습니다.
- BatchNorm 버그가 있어도 왜 에러 없이 학습되는지(0:46:00 부근 댓글). S09 뜻 풀이와 같습니다.
- `self.training` 철자 실수로 몇 시간 허비(댓글). 앱 노트북에 철자 확인 셀을 둡니다.
- 다차원 모양과 곱셈 따라가기 어려움(댓글). 리서치 제안대로 층마다 입출력 모양을 표로 보여 주는 "모양 추적기"를 S06에 붙입니다.

교사 몽키 예상(강의 지식 기반):
- 3차원 텐서 모양 상상하기. 앱은 [B, T, C]를 상자 그림으로 보여 줍니다.
- view와 squeeze.
- 학습이 길어져 기다림. 축소 설정(반복 횟수 줄이기)도 함께 제공합니다.
- 결과 손실이 영상 숫자와 조금 다름. 범위로 판단합니다.
