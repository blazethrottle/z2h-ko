### 0.3 숫자·빈 값
- 진도, 시간, 단계 위치, 타임스탬프는 `tabular-nums`.
- 값이 없으면 "–" (en dash 하나). 0과 "–"는 다르다: 0은 기록이 있는데 0, "–"는 아직 기록이나 정의가 없음.
- 변화는 "▲+3", "▼-1"처럼 기호 + 부호 + 숫자. 색은 `ink-muted` 그대로 둔다 (좋고 나쁨을 색으로 판정하지 않음).

### 0.4 문구 원칙
- 존댓말, 짧게. 연속 기록(스트릭), 순위, "벌써 3일째 안 하셨어요" 같은 죄책감 문구, 축하 폭죽 없음.
- 틀렸을 때는 "다시"와 이유만. "아쉬워요", "틀렸습니다!" 같은 감정 문구 없음.
- em dash(U+2014) 금지. 범위는 en dash(–) 또는 "~".

### 4.2-1 바뀐 줄만 보여 주기 (`c7_edits`, D52, data-spec v1.2 `edits`)
- 쓰는 곳: `edits`가 비어 있지 않은 단계 (앞 셀을 고치는 단계, 01편 예: S05, S09b, S10, S10b, S11b, S13, S13b, S13c, S16). `edits`가 비면 지금처럼 새 셀.
- 머리 띠 `paper-sunken`: "바뀐 줄만 · L01-S04 Value 클래스 셀" (`target_step`의 셀 이름) + 보조 "전체 보기" (`aria-expanded`) + "⧉ 넣을 줄 복사". 아래 한 줄 "흐린 줄은 이미 있는 기준 줄입니다. 그 바로 아래에 밝게 표시한 줄을 넣습니다."
- 고칠 곳마다: "1 / 3 · `where_ko` · n줄 넣기" (replace면 "n줄 바꾸기") → 코드 상자: `…` / `anchor_line` (`code-lineno` 색, 흐리게) / 넣을 줄 (`code-bg-sel` 바탕 + 왼쪽 3px `code-keyword` 막대) / `…`. `anchor_line`이 null이면 "셀 맨 아래"라고 쓰고 기준 줄 없이 보인다. 넣을 줄은 `code`의 앞쪽 줄을 `edits` 순서와 `line_count`대로 나눠 쓴다. 나머지 줄은 아래 새 셀 블록.
- replace: 기준 줄 대신 바뀌기 전 줄을 `code-lineno` + 취소선 없이 "바꾸기 전" 꼬리표로 한 줄, 그 아래 바뀐 뒤 줄 강조 (색만으로 구분하지 않도록 꼬리표 글자를 함께).
- "전체 보기": 고친 뒤 셀 전체를 펼치고 새로 넣은 줄을 같은 강조로 표시. diff 기호(+/-)는 쓰지 않는다.
- `rerun_first`가 있으면 위에 안내 "먼저 다시 실행: L01-S04 셀" + 단계 링크. 오른쪽(모바일은 아래)에 줄별 풀이 (넣는 순서대로), "다시 실행했어요".

### 4.3 결과 확인 (`expected_check.type`별)
| 유형 | 화면 |
|---|---|
| `output_match` | "내 결과 붙여넣기" + "비교하기". 앞뒤·줄 끝 공백과 줄바꿈 종류 무시, 첫 다른 줄과 다른 부분 표시. ✓ "맞음: 보여야 하는 것과 같습니다." / ✕ "다시: {어디가 다른지}. {볼 곳}" |
| `value_range` | 숫자 하나 입력칸 + "확인". 범위 안이면 ✓. 범위는 단계 데이터 |
| `manual` | 예상 출력 아래 "내 화면도 이렇게 나왔나요?" 버튼 둘: "같아요" (✓) / "달라요" (힌트 카드로 안내). 그림·그래프 단계 (예: L01-S01 포물선) |
- 붙여 넣은 글에 `Traceback` 또는 `Error`가 있으면 결과 대신 **에러 읽기 도우미** (F-P7의 4단계 읽는 순서)를 먼저 보인다. 힌트 사용으로 세지 않는다 (hints.md 2절).
- ✕가 나와도 힌트를 자동으로 열지 않는다. 힌트 카드 테두리만 `accent`로.
- "비교하기"·"확인" 누름을 힌트 열림 조건의 "시도 1회"로 센다 (decisions C4).

접근성: 모바일 줄 `role="button"` + `aria-expanded`. 데스크톱 2단도 DOM은 코드 줄 다음 풀이. 세 칸의 가려진 칸은 `aria-hidden`이 아니라 "가려짐, 예측 뒤 열림" 글자로 읽힘.

## 5. 확인 문제 (`s5_quiz`, D25·D26)
- 머리: "01 micrograd · 확인 문제 · 단계 1~7 범위", "답을 내면 풀이가 열립니다. 틀린 문제는 복습 카드로 다시 나옵니다."

- 유형별 답 칸
  | 유형 (`type`) | 답 칸 | 채점 (`auto_grade.type`) | 힌트 |
  |---|---|---|---|
  | 고르기 `choice` (D35) | 보기 목록 `role="radiogroup"`, 행 최소 `size.option-h`, 번호 원 + 글자. 고른 행 2px `accent` + `accent-tint` + "고름". 마지막 보기가 "모르겠어요"일 수 있음 | `choice`: 고른 번호 = `answer_index` | 있음 (확인 문제일 때). 모르겠어요는 감점 없이 오답 기록, 추천에만 씀 |
  | 결과 예측 `predict` | 한 줄 입력 | `exact` 또는 `numeric_range` | **없음**. 틀려도 감점 없이 풀이로 이어짐 |
  | 내 말로 설명 `explain` | 긴 답 `textarea` (최소 120 높이, Pretendard) | `keywords` 또는 `manual` | 있음 |
  | 버그 고치기 `fix_bug` | 코드 조각 + 한 줄 또는 여러 줄 입력 (`font-code`) | `exact` / `keywords` | 있음 |
  | 적용하기 `apply` | 여러 줄 입력 | `numeric_range` / `manual` | 있음 |
- 결과 상자: ✓ "맞음" / △ "절반 (흔들림)" (`paper-sunken` 바탕, `ink`) / ✕ "다시". 아래 점수 줄 "점수 0.5 / 1" + 이유 ("힌트 없이", "힌트 2단계 · 80%로 계산").
- **채점 기준 체크 목록** (`rubric`): explain 제출 뒤 열림. "채점 기준: 내 설명에 들어 있는 것을 고르세요". 항목마다 체크박스 행 (최소 44, `line-strong` 테두리) + 오른쪽 배점 ("0.5점"). 고른 합이 점수. `manual` 모드에서 CTO가 나중에 수동 채점하면 같은 목록을 채점자가 씀. `keywords` 모드면 앱이 미리 체크해 두고 사용자가 고칠 수 있게 함 (이 경우 "자동으로 고른 것" 표시).
- 끝: 다음 줄 ("다음: L01-Q05 · tanh 노드의 기울기 (결과 예측)") + "이전 문제" / 주 버튼 "다음 문제".

- 유형은 5개 (D35). 고르기는 "제출"을 눌러야 채점하고 풀이를 연다. 기초 진단 F-D1~D5도 같은 고르기 카드를 쓴다. 데스크톱은 3열.

## 6. 힌트 사다리 (`s6_hints`, D10·D24·D26)
- 단계: 1 질문으로 생각하기 (H1) → 2 개념과 위치 짚기 (H2) → 3 빈칸 코드 (H3) → 4 정답과 줄별 풀이 (H4) → 도움 요청 메모 (HELP).
- 한 번에 다음 한 칸만 버튼이 보인다. 첫 칸만 주 버튼, 나머지는 보조 버튼.
- 열림 조건 (hints.md 2절): H1 언제나 / H2 H1 뒤 시도 1회 / H3 H2 뒤 시도 1회 또는 15분 / H4 H3 뒤 시도 1회 또는 30분 / HELP H4 뒤에도 결과가 다를 때. 잠긴 칸 오른쪽에 조건 글자 ("답을 한 번 더 내거나 15분 뒤 열림"). 조건을 채우면 "지금 열 수 있습니다."
- **점수 영향 문구** (확인 문제에서만, 버튼 바로 위 `caption` `ink-muted`):
  - H1: "이 힌트는 점수에 영향이 없습니다."
  - H2: "이 힌트를 열면 이 문제는 80%로 계산됩니다."
  - H3: "이 힌트를 열면 이 문제는 50%로 계산되고, 다음 복습에 다시 나옵니다."
  - H4: "이 힌트를 열면 이 문제는 0%로 계산됩니다. 완료는 인정되고, 내일 비슷한 새 문제로 다시 해 볼 수 있습니다."
  - 실습 단계: 문구 대신 카드에 "실습 단계는 점수가 없어서 힌트를 열어도 완료로 셉니다."
  - 감정어("아쉽게도", "벌써") 없음. 숫자와 결과만.
- H2가 기초 단위(F-xx)를 가리키면 내용 아래 링크 "기초 F-M2 연쇄 법칙 감각으로 돌아가 보기 ↗" (D24). 그 단위 복습 카드가 1일로 되살아남 (review.md 5절).
- H3: 빈칸 코드 블록 (`code_with_blanks`, `___`). H4: 정답 코드 + 줄별 풀이 + "왜 틀렸을 가능성이 큰가" 한 줄.
- 도움 요청 메모: "정답을 넣어도 결과가 다르면 대개 설치나 장치 문제입니다. 내 코드, 에러 마지막 줄, 환경을 정리한 메모를 만듭니다. 이 화면에만 저장되고 자동으로 보내지 않습니다." 보조 버튼 "메모 만들기" → 메모 보기 + "복사". 보내기 버튼 없음.
- 기록: "이 문제 힌트: 2 / 4 · 이 문제는 80%로 계산됩니다". `max_hint_level` 저장. 홈에는 보이지 않음.
- 결과 예측 문제에는 사다리를 보이지 않는다.
- 위치: 데스크톱 오른쪽 패널, 모바일 같은 화면 아래. 목업 `s6`은 상태 설명용 (A 안 엶, B 3단계 열림, C 4단계 + 도움 요청).
- 접근성: 열면 새 힌트 제목으로 포커스, `aria-live="polite"`.

## 7. 복습 (`s7_review`, D22)
- 머리: "오늘 5장 · 약 12분 / 하루 최대 25분 · 1 / 5". 카드마다 예상 분 (기본: 개념 3분, 예측 2분, 손 8분, CTO가 실제 기록으로 보정).

  |---|---|---|---|
  | 틀렸어요 | 놓침 `miss` | 1일 | "1일 뒤 다시" |
  | 헷갈려요 | 흔들림 `shaky` | 같은 간격 한 번 더 | "3일 그대로" |
  | 기억났어요 | 통과 `pass` | 다음 간격 | "7일 뒤" |
  주 버튼은 "기억났어요" 하나. 세 버튼 모두 최소 56 높이, 390 폭에서 3열(420 미만은 1열).

- 오른쪽(데스크톱) / 아래(모바일): 오늘 남은 것 (종류 배지, 출처 id, 간격, 예상 분), 다음 복습 (날짜별 장수·분), 규칙 설명 "기억났어요는 다음 간격으로, 헷갈려요는 같은 간격을 한 번 더, 틀렸어요만 1일로 돌아갑니다. 25분을 넘는 날은 간격이 긴 카드를 하루 미룹니다. 빼먹은 날도 벌점은 없습니다."

- 빈 상태: "오늘 복습할 것이 없습니다." + 다음 복습 날짜.
